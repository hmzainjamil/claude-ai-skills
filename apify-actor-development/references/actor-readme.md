# Actor README guidelines

Use an Actor README to explain one specific Actor to its users. Base every claim on that Actor's source, input/output schema, current settings, and tested behavior. This file is a writing checklist, not an Actor Store policy or legal assessment.

## Suggested sections

- **Purpose and limits:** What the Actor does, what it does not do, and which target sites or data types it supports.
- **Input:** Required and optional fields, defaults, valid values, and a link to the actual input schema.
- **Output:** Fields and types from the output schema, plus a small example checked against real output.
- **Run instructions:** Current Actor Store or CLI steps, with the tested version and any required permissions.
- **Limits and costs:** Current pricing and compute behavior from the Actor's configuration or Store listing. Date time-sensitive facts.
- **Errors and support:** Common source-backed failure modes, support route, maintainer, and update date.
- **Data and legal considerations:** Describe the data the Actor can collect and where it is sent or stored. Require users to check applicable laws, target-site terms, and platform rules.

## Evidence and safety

Do not promise rankings, rich search results, traffic, savings, accuracy, safety, or legal compliance without evidence for that exact Actor. Do not use a generic disclaimer that claims public data collection is automatically ethical, lawful, or safe. Publicly visible information can still be personal data. A disclaimer does not replace a review of the Actor's actual behavior, data handling, or user obligations.

Keep examples aligned with the checked schema and current interface. Never invent output fields, pricing, free-tier limits, or platform capabilities. Mark untested commands and examples as unverified.
